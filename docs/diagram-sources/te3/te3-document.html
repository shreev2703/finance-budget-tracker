LedgerLogic is a web app that helps college students log income and expenses, see their monthly balance, and stay under per-category spending limits, with a warning at 80% of a limit. This document contains all of our TE3 diagrams: the UML class diagram for our domain model, how each user story maps to the classes, our initial UML sketch, and our UI mockups.

1. UML Class Diagram (Domain Model)

How to read the diagram

NotationMeaning
- (minus)Private attribute. Every attribute is private, so other classes cannot read or change an object's data directly.
+ (plus)Public method: the only way other classes use an object (getters such as getAmount(), and operations such as setLimit() and validate()).
1 / MMultiplicity: 1 = exactly one, M = many (zero or more). Example: one User records M Transactions; each Transaction belongs to 1 Category.
Solid arrowAssociation: the class at the tail holds a reference to the class at the head.
Hollow diamondAggregation: a MonthlySummary includes the Budgets for that month.
Dashed arrowDependency: the class uses the enumeration or reads the other class's data.

Design notes. Money is stored as integer cents (amountCents, limitAmountCents) to avoid rounding errors; the public getters return dollars. Every class except the enumerations carries a userId, so each user only ever sees their own data. A user has at most one budget per category per month. Filtering history (US-06) is a query through User.getTransactions(period), not a separate class. A SavingsGoal class was considered and left out because no TE2 story requires it.
